# Три альтернативы совета + свечной график в карточке позиции

Дата: 2026-08-05. Статус: одобрено Алексеем («Делай делай», график — в карточку).

## Часть 1 — три альтернативы совета

`src/lib/advice.ts`, существующие `adviseForPosition`/`adviseNoPosition` не
меняются (их использует CLI). Добавляется:

- `Advice` расширяется полями `risk: "low" | "medium" | "high"` и
  `recommended?: boolean` (опциональны, старый код не ломают).
- `adviseAlternatives(view: PositionView | null, m: MarketState): Advice[]` —
  всегда три элемента:
  - **low** — закрыть позицию / не заходить (в risk-off и storm — с текущими
    формулировками причин); издержки — стоимость выхода.
  - **medium** — ребаланс/вход в диапазон по уровням `suggestRange`
    (низ — поддержка, верх — сопротивление).
  - **high** — узкий диапазон, прижатый к сопротивлению: низ — цена −1%,
    верх — ближайшее сопротивление (touches ≥ 2, в пределах +2…+25%);
    фолбэк без сопротивления — ±ATR вокруг цены.
- Для medium/high — оценка carry: комиссии масштабируются по концентрации
  (отношение суммарных ширин), гамма-издержки — `lvrPerDay` на новых границах.
  Помечено как оценка.
- `recommended` по режиму: risk-off/storm → low; calm → high;
  normal/trend-up → medium.

`src/server.ts`: `/api/positions` дополнительно кладёт в каждую позицию
`alternatives: Advice[]`, для пустого кошелька — `walletAlternatives`.
Существующие поля `advice`/`walletAdvice` остаются.

UI: вместо одного блока совета — три в грид-раскладке, бейджи
🟢 низкий / 🟡 средний / 🔴 рискованный, рекомендуемый подсвечен рамкой
и меткой «рекомендуем». В каждом — конкретные цены, стоимость, что даст.

## Часть 2 — свечной график в карточке позиции

### Хранилище (src/lib/candles.ts)

- `ensureCandleStore(product)` — годовая история часовых свечей в
  `.cache/store-<product>-1h.json`. Первый вызов — бэкфилл 365 дней с
  Coinbase (~30 запросов, 10–25 сек, один раз), дальше — дотяжка свечей
  с последней сохранённой. Повторная дотяжка не чаще раза в 15 минут
  (in-memory троттлинг).
- `aggregateCandles(candles, tf)` — агрегация 1h → 4h / 1d / 1w (недели с
  понедельника) / 1M (календарный месяц UTC).
- Существующий `fetchHourlyCandles` не меняется; общий низкоуровневый
  фетчер диапазона выделяется и переиспользуется.
- Фон: сервер при старте и раз в 15 минут дотягивает store для всех
  продуктов, которые уже запрашивались (стартово — SOL-USD).

### API (src/server.ts)

`GET /api/candles?product=SOL-USD&tf=1h|4h|1d|1w|1M` →
`{ product, tf, candles: [{time, open, high, low, close}...],
   levels: { price, supports, resistances, suggestedRange } }`.
Уровни считаются из тех же store-свечей (`computeTA` + `suggestRange`),
без второго похода в Coinbase. Неизвестный product → 400.

Продукт по паре позиции: не-стейбл токен пары → `<SYMBOL>-USD`,
белый список Coinbase-продуктов: SOL, ETH, BTC. Прочие пары — карточка
без графика с подписью «график недоступен для этой пары».

### UI (public/index.html)

- `lightweight-charts` (standalone, из npm) кладётся в
  `public/vendor/lightweight-charts.standalone.production.js`, коммитится;
  CDN не используется.
- В карточке позиции под шкалой диапазона: контейнер графика (~300px)
  + кнопки таймфреймов 1ч/4ч/1д/1н/1М. Свечи; поверх — price lines:
  поддержки (зелёный пунктир), сопротивления (жёлтый пунктир),
  границы текущего диапазона позиции (синие сплошные).
  Тёмная тема в палитре приложения. Ленивая загрузка после рендера карточки.

кошельком — три совета и график. Коммит разрешён пользователем.
