# Журнал сделок торгового кошелька

Дата: 2026-08-05. Статус: одобрено Алексеем (уточнения учтены).
Контекст на будущее: поверх журнала планируется «фонд» — доли вкладчиков
(Алексей, девушка, друг), поэтому события переводов несут поле
`contributor` (пока null).

## Хранилище

`data/` (в .gitignore — репозиторий публичный, кошелёк и комментарии не утекают):
- `journal-<wallet>.json` — `{ wallet, newestSignature, backfillBefore,
  backfillDone, events[] }`;
- `balances-<wallet>.json` — `{ snapshots: [{time, walletUsd, positionsUsd,
  pendingUsd, totalUsd}] }`.

## Сканер (src/lib/journal.ts)

- Полная история: `getSignaturesForAddress` страницами по 1000 до конца
  (первый прогон — минуты на публичном RPC), прогресс (`backfillBefore`)
  сохраняется — обрыв не теряет работу. Дальше — инкрементально до
  `newestSignature`. Синк идёт в фоне, не блокирует API.
- Каждая транзакция (`getTransaction jsonParsed`):
  - **Суммы** — экономические дельты кошелька: SOL (post−pre, без сетевой
    комиссии) + дельты токен-аккаунтов кошелька по минтам.
  - **Сетевая комиссия** — `feeSol`, сохраняется если fee payer — кошелёк.
  - **Классификация** — по дискриминаторам инструкций Whirlpool
    (open/close/increase/decrease/collect, v1/v2/TokenExtensions);
    приоритет open > close > increase > decrease > collect. Без
    Orca-инструкций: чистое поступление → `deposit`, чистый расход →
    `withdraw`, иначе `other`.
  - **Диапазон сделки** — тики из данных open-инструкции (offsets по
    дискриминатору), цены = 1.0001^tick·10^(decA−decB); decimals — из
    tokenBalances транзакции, пул определяется fetchWhirlpool по
    аккаунтам инструкции (кэш). close/decrease наследуют диапазон от
    последнего open/increase той же позиции.
  - **USD-оценка** — историческая цена SOL из годового store свечей
    (`ensureCandleStore`), стейблы 1:1. Старше года — цена null, событие
    остаётся с количествами.
- Событие: `{ signature, blockTime, type, solDelta, tokenDeltas{символ:Δ},
  valueUsd, feeSol, position?, range?{lower,upper}, priceUsd?,
  contributor: null, comment: "" }`.

## Баланс и динамика

Снапшот пишется после каждого успешного `/api/positions`:
`walletUsd` (SOL+стейблы кошелька) + `positionsUsd` + `pendingUsd`
(несобранные комиссии; в Orca они уже нетто — протокольная доля вычтена
на уровне пула). Показатели журнала:
- текущий баланс с разбивкой (кошелёк / позиции / несобранные комиссии);
- **чистая прибыль с начала работы** = текущий баланс − (Σ поступлений −
  Σ выводов) по журналу — база будущих долей фонда;
- изменения за 24ч / 7д / 30д — по ближайшим снапшотам (если снапшотов
  ещё нет — «н/д»).

## API (src/server.ts)

- `GET /api/journal?wallet=` → `{ syncing, progress, syncedAt, events
  (новые сверху), balance, netDepositedUsd, pnlSinceStartUsd,
  changes{d1,d7,d30} }`. Запускает фоновый синк, если не идёт и данные
  старше 60 сек; отвечает сразу текущим состоянием.
- `POST /api/journal/comment` `{wallet, signature, comment}` — сохранить
  комментарий события (поиск по signature).

## UI (public/index.html)

Возвращаются вкладки: «Позиции» | «Журнал». Вкладка журнала:
- stat-плашки: баланс, чистая прибыль с начала, Δ7д, Δ30д;
- баннер «⟳ Синхронизация истории… обработано N» при `syncing`;
- таблица: дата · бейдж типа (поступление/вывод/вход/выход/сбор/прочее) ·
  суммы (токены и USD) · диапазон сделки · цена SOL · fee · комментарий;
- комментарий — инлайн: клик → textarea → «Сохранить» → POST;
- автообновление активной вкладки общим механизмом.
